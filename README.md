# CryptoTG

CryptoTG - учебный демонстратор зашифрованного чата для лабораторной работы. Проект показывает идею обмена сообщениями между пользователями, которые знают адрес/подсеть друг друга и общий ключ шифрования.

Важно: это не production-мессенджер и не готовое средство для секретной переписки. Проект полезен как учебный пример: можно увидеть, что без правильного ключа сообщение не превращается в читаемый текст, а также разобрать типичные ошибки в проектировании защищенных приложений.

## Что умеет проект

- Многопользовательский чат через Flask + Socket.IO.
- Группировка пользователей по подсети.
- Публичные и приватные сообщения.
- Клиентское шифрование сообщений общим ключом.
- Веб-клиент и отдельный Tkinter-клиент.
- Минимальная серверная админка для мониторинга подключений.

## Что улучшено

- Новые сообщения шифруются через AES-256-GCM, а не AES-CFB.
- Добавлена проверка целостности: при неверном ключе AES-GCM не возвращает случайный текст как будто все нормально.
- Старые AES-CFB сообщения оставлены в режиме совместимости только для чтения.
- PBKDF2-HMAC-SHA256 усилен до 200 000 итераций для новых сообщений.
- Сервер больше не доверяет `username` и `subnet_hash` из сообщения, а берет отправителя из зарегистрированной WebSocket-сессии.
- Добавлена базовая валидация имени пользователя, подсети, IP и длины сообщения.
- Административные WebSocket-команды и HTTP-методы мониторинга защищены `ADMIN_TOKEN`.
- Локальная база, `__pycache__` и другие runtime-файлы вынесены в `.gitignore`.
- Добавлены unit-тесты для новой криптологии и обратной совместимости.

## Установка

```bash
git clone https://github.com/zheyas/CryptoTG.git
cd CryptoTG
pip install -r requirements.txt
```

## Запуск веб-клиента

```bash
python3 client/client.py
```

После запуска откройте:

```text
http://localhost:5001
```

По умолчанию клиент пытается подключиться к публичному серверу:

```text
https://cryptotg.onrender.com
```

URL сервера можно изменить в интерфейсе.

## Запуск собственного сервера

```bash
export SECRET_KEY="replace-with-random-flask-secret"
export ADMIN_TOKEN="replace-with-admin-token"
export CORS_ALLOWED_ORIGINS="*"
python3 server/app.py
```

Переменные окружения:

- `SECRET_KEY` - секрет Flask-сессий.
- `ADMIN_TOKEN` - токен для административных действий и API мониторинга.
- `CORS_ALLOWED_ORIGINS` - разрешенные CORS origins для Socket.IO.
- `MAX_MESSAGE_LENGTH` - максимальная длина сообщения, по умолчанию `4096`.

## Шифрование

Новый формат сообщения:

```text
v2:Base64(salt[16] + nonce[12] + ciphertext_with_gcm_tag)
```

Параметры:

- алгоритм: AES-256-GCM;
- деривация ключа: PBKDF2-HMAC-SHA256;
- итерации PBKDF2: 200 000;
- соль: 16 байт на каждое сообщение;
- nonce: 12 байт на каждое сообщение.

Старый формат `Base64(salt[16] + iv[16] + ciphertext)` на AES-CFB поддерживается только для расшифровки старых сообщений.

## Ограничения

- Общий пароль вручную вводят все участники, автоматического обмена ключами нет.
- Аутентификации пользователей нет: это учебная модель, а не полноценная учетная система.
- Сервер видит метаданные подключения: имена, IP, подсети и факт обмена сообщениями.
- Подсеть используется как учебная логика группировки, а не как строгая модель доверия.
- Для реального защищенного мессенджера нужны отдельная модель угроз, проверенный протокол, управление ключами, аудит и защита клиентов.
